## Honest findings about the LOOP (not the pipeline)

**F1 — Breadth gap (the big one).** Every validation since cycle 1 ran the SAME 4 legs.
Cycles 2–2d changed shared evidence paths that affect **every** leg (same-check wording,
identical-fact semantics, fire-rate facts, the verifier's fact-priority rules) — yet 26 of
the ~30 burned-pool legs have never been re-run under the new code. The plan said "iterate on
the burned pool"; the practice narrowed to 4 legs. Risk: silent regressions elsewhere (e.g.
the terminal-identical rule interacting with partial-fix catches on legs we haven't looked
at). **Required before any cycle-3 work is trusted: one full burned-pool sweep on the current
code.** (~30 legs ≈ 3.5–4.5M gpt-5.4 tokens — a deliberate spend, needs sign-off.)

**F2 — Single-roll claims.** Per-leg "fixed"/"regressed" was repeatedly declared off one roll
each — the exact methodology error the 3-arm analysis documented. Math-30's oscillation is
partly synthesis-roll variance layered on real mechanism changes. Rule going forward: a leg
counts as FIXED only after 2 consecutive rolls with the correct verdict AND the mechanism
visible in the trace; a REGRESSION claim equally needs the mechanism identified, not just the
flipped verdict.

**F3 — Thread depth vs. breadth.** 2b/2c/2d were three same-day iterations on one fact's
wording, selection-pressured by 2 legs. Each fix individually passes the statement test
(earned-identical; observed-vs-observed; kv-pairwise; terminal-identical are all
bug-agnostic), so this is not overfitting in the rule-content sense — but the *choice of what
to fix next* was driven by 4 bugs, which is its own narrowing. The untouched G3 recall thread
(zero-non-seed-power convergence gate, fire-ratio screening rejection, receiver-state
variation port) very likely has more marginal value now than a 2e.

**F4 — Missing stop/pivot rule.** Adopted now: **after two consecutive same-thread hotfixes,
the next action must be a breadth measurement, not a third hotfix.** (Applied retroactively:
2d was the third; the next run after c2d must be the pool sweep, not a 2e.)

**F5 — Cost ledger (absent until now).** Pipeline validation spend so far: c1flag 0.54M +
c2flag 0.63M + c2b 0.76M + c2c 0.61M + c2d (~0.6M est) + nano abort 0.09M ≈ **3.2M pipeline
tokens**; sub-agent (analysis + implementation) spend ≈ 0.9M. Sustainable, but the pool sweep
roughly doubles it — track per-cycle in the cycle log from now on.

**F6 — What is working and must be kept.** Fixture-first (every VM-observed wrong fact became
an offline regression test the same day); mechanism-attributed triage before any next change
(three times this caught that the "obvious" causal story was wrong — Closure-70's diagnosis,
Math-68's byte-identical buggy message, Math-30's kv-shape); disjoint-territory parallel
implementation (7 Opus agents, zero merge conflicts); archive-verify-prune hygiene (now
including run dirs, after a lapse); every wrong verdict traced to a named mechanism before
any code was written.

## Direction verdict

The trajectory is right: two of the three robust FP classes are mechanically dead or cornered,
the fact layer is measurably honest (facts appear verbatim in live traces and are covered by
tests), and recall was protected through the precision work (the one FN regression was caught
in one cycle and root-caused to variance, not the fix). The loop's next moves, in order:
1. **c2d triage**, then **full burned-pool sweep** (F1/F4) — the real cycle-2 score.
2. **Open the G3 recall thread** (cycle 3) — no more precision hotfixes on the 4-leg set.
3. Fresh confirm on the ~12 unseen dev bugs only after the pool is stable; holdout stays
   sealed.

## Standing retrospective protocol (run at every cycle boundary)

At the end of each cycle, append to the cycle doc:
1. **Trajectory table** — per-leg verdicts across ALL validation rolls to date (not just the
   latest), with the two-consecutive-rolls rule applied to any FIXED/REGRESSED claim.
2. **Statement-test audit** — restate every shipped change without naming a bug; if it can't
   be restated, revert it.
3. **Breadth check** — list which burned-pool legs have NOT been re-run since the oldest
   still-unvalidated change; if the answer spans a class boundary, schedule a sweep.
4. **Cost line** — pipeline + agent tokens this cycle, cumulative.
5. **Pivot decision** — continue thread / switch thread / breadth run, with the
   two-hotfix rule (F4) binding.
