# Cycle 3b — universal screening (envelope v0) + generation-side recall package (specs)

Status: IN PROGRESS 2026-07-25. Approved plan: generation-first recall lever + universal
precision fact; cross-run confirmation held in reserve pending measurement. Statement test:
no bug names in requirements.

## Spec M — universal screening: every check is measured, whatever door it was born through

**Problem.** Relations pass screening (buggy fire-ratio measured, stats recorded); checks
invented directly inside harnesses do not — they reach judging with no measurements, and all
residual wrong convictions ride on exactly such unmeasured fresh inventions. The fire-rate /
intrinsic facts are proven live (they killed a fresh invention when delivered); the gap is
pure coverage.

**Requirement.**
1. After harness acceptance, for each accepted harness, extract each `[oracle:<id>]` check's
   body (the code region guarding/composing that alarm — reuse/extend the existing per-oracle
   parsing in java_source if present; a conservative extractor is fine: the enclosing
   method/block that throws that id; on extraction failure, skip that oracle, fail-open).
2. Run each extracted check through the SAME screening measurement relations get (the
   relscreen counting wrapper on the BUGGY build, same runs budget), yielding
   (checked, violated) per oracle id. Bounded: skip oracles already matched to a screened
   relation (one-door already covers them); cap at 8 screens per leg, prioritizing oracles
   that FIRED on the patched build if ordering matters (screen lazily at judging time for
   fired oracles only — implementer's choice; lazy-at-judging is cheaper and covers exactly
   what matters).
3. Store stats in a per-leg map; at the harness-firing judging site, deliver
   `fire_rate_fact(...)` from these stats exactly as one-door does for matched relations —
   plus, when the check held on ZERO buggy inputs (violated == checked > 0), a stronger
   universal fact: "this claim has NEVER been observed to hold on the buggy build
   (0/<checked> inputs in its own declared domain) — a correctness claim the known-mostly-
   correct build never once satisfies is unverified speculation, not a contract."
4. Fail-open everywhere: extraction/compile/run failure → no fact, never a drop.

## Spec N — generation-side recall package

1. **Convergence gate:** the campaign may not finish while the leg's total NON-SEED buggy
   detections across all kept relations/harness checks is zero (a seed detection = fires only
   on the failing test's own literals; the screen's non-seed counts exist per relation).
   While zero and under a bound (max +2 extra rounds), request another synthesis round with
   the existing machinery. Loud print each time: "[convergence] arsenal has zero non-seed
   detection power — requesting round N".
2. **Receiver-state variation instruction:** add to the relation-synthesis prompt one
   generation directive (dataset-neutral): for any rejection/error contract ("asking for X
   that is absent/invalid must throw"), also generate a variant that holds the probe input
   FIXED and varies the receiver/container state (contents, size, installed elements) —
   rejection behaviour must not depend on unrelated state. One directive block, no examples
   from any bug.
3. No other synthesis-prompt changes (the diag-24 lesson: pressure to assert is toxic;
   pressure to EXPLORE STATE with existing oracle discipline is the safe form).
