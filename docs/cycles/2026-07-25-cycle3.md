## Spec J — re-armed mechanical identical-drop with the trigger-input exemption

Replaces the defused drop (fb35ce9). At both earned-identical sites in run.py (same-check
branch, muted-replay branch), when `value_verdict == "identical"` and the leg is semantic:

1. Compute two mechanical flags via new pure helpers in evidence_facts.py:
   - `expected_is_test_literal(fired_msg, trusted_values) -> bool` — the fired message's
     EXPECTED-side value (expected=/tagged, or the full literal string for non-numeric
     messages) matches one of the failing test's own assert literals. Distinctiveness rule:
     a numeric match counts only if the literal has ≥4 significant digits; a string match
     only if ≥8 chars after whitespace-normalization. (Guards against bare 0/1 matches.)
   - `fired_at_test_input(fired_msg, trigger_literals) -> bool` — any distinctive trigger
     seed literal (same distinctiveness rule) appears among the fired message's key=value
     values. `trigger_literals` from `trigger_seed_literals(failure_tests)` (already
     importable in run.py).
2. Decision ladder (mechanical, in this order):
   a. `expected_is_test_literal` AND the real failing test passes on the patched build (the
      fact already established at these sites) → **mechanical dismiss**: the check re-asserts
      the test's own pinned expectation, the real test passes, and the copy fires identically
      on both builds — its setup diverged from the test. Reason tag `IDENTICAL-DISMISSED
      (setup-divergence)`.
   b. else `fired_at_test_input` → **keep**, attach a keep-leaning fact: identical behaviour
      at the failing test's own inputs on an observable the test does NOT pin is the
      patch-failed-to-fix pattern (the root defect survived the patch) — proceed to normal
      judging with that fact.
   c. else → the narrow family-duty question (existing `family_duty`); NO → **mechanical
      dismiss** (`IDENTICAL-DISMISSED (family-duty)`); YES → keep and proceed.
3. Every mechanical dismissal prints one `[identical-drop]` line and lands in drop_reasons —
   the validation run's kill-switch criterion counts them: **if any dropped firing sits on an
   overfit leg that ends missed, the drop defuses again** (triage step, not in-code).
4. Fail-open everywhere: any helper/LLM error → keep and proceed to normal judging.

Fixtures (tests): the four pool30/prior cases as message-level fixtures —
(setup-divergence case: expected literal = test literal string, test passes → dismiss);
(root-defect case: fired at test-input params, expected NOT a test literal → keep + fact);
(neither: family-duty NO → dismiss); trivial-literal guard (test literal `0`/`1` must NOT
qualify for either flag).

## Spec K — one-door fact parity for harness-track firings

**Problem (proven within-leg):** replay-track firings carry screen stats/fire-rate facts;
harness-track firings of the SAME underlying check do not, and the judge convicts there.

**Requirement.** When a harness-track firing is judged (rv.verify evidence assembly):
1. Mechanically match the fired oracle to a screened relation: normalized-id match
   (lowercase, strip non-alnum) between `[oracle:<id>]` and relation names, else a
   shared-distinctive-token match (≥6-char token overlap between the fired message's check
   text and a relation name). Conservative: no match → no fact (never guess).
2. On match: attach the same `fire_rate_fact(...)` (screen stats + replay patched counts if
   that relation was replayed) and the relation's screen-decision reason (demotion notes
   included) to the firing's evidence.
3. Also attach, for EVERY harness firing where the acceptance-time buggy keep-going scan
   recorded per-oracle counts, that oracle's buggy-side rate (data already in latent_map /
   scan output; only wire what exists — no new executions).

## Spec L — evidence-destroying alarm lint (boolean-swallow)

A check that catches an exception and records only a bare flag (`catch (...) { x = false; }`
with no rethrow and no use of the caught exception in the alarm message) destroys the
exception identity every downstream pre-existing/laundering guard needs.

1. New lint `boolean_swallow(check_source) -> reason|None` beside the existing
   `violation_swallowed` lint (same module), detecting: a catch block whose body only
   assigns literals to variables (no rethrow, no `e` reference escaping), where a later
   throw/alarm conditions on that variable.
2. Apply at relation screening (drop, like the other lints, loudly) AND at harness
   acceptance (the campaign's existing gate-0 lint family): reject the harness attempt with
   the lint reason so the model regenerates.
3. Fixture: the archived boolean-swallow harness source (pool30
   `11_patch1-Chart-26-Jaid_c/trace.md`, the `success=false` block) → lint fires; a
   catch-and-rethrow-with-cause source → lint quiet; catch-and-return (input rejection
   skip) → lint quiet (that pattern is legitimate and mandated).
