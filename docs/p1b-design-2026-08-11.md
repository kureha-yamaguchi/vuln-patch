# p1b — the firing-state reference gate (design, 2026-08-11)

Design only. No code was changed, no run was launched, nothing was pushed to
the VM, `docs/plan.md` was not edited.

This is the gate-side half of 8.4x. p1a built the recording (`RecFDP`
consumed-value log, `capture_receivers` + the reflection state printer, the
untruncated persistence fixed at both replay sites in 8.31). p1b is the
decision logic that was deliberately deferred until real recorded lines
existed. They now exist.

## Stations this design targets

## 0. The rule, in two sentences

When a convicting relation's firing carries a recorded receiver state, and the
leg admitted a reference implementation for the very observable that firing
disputes, we evaluate that reference at the firing's own recorded state and
compare its answer with the two numbers the firing itself printed — the
patched build's observed value and the relation's claimed expected value.

Reference agrees with the patched build → the relation's expected value is
wrong and the firing is spurious (dismissal-eligible); reference agrees with
the relation and disagrees with the patched build → the conviction is
corroborated; everything else — the two disagree with each other, the state
does not map, the receiver never ran, a value is truncated or NaN, no
reference exists — is ABSTAIN, which is byte-for-byte today's behaviour.

### 0.1 The exemplar, arithmetic verified by hand

From `runs-archive/runs/stack_confirm_20260810_140852/06_patch1-Math-65-CapGen_c/result.jsonl`,
one of the 36 doubly-flagged convictions
(`rms_matches_documented_mean_of_weighted_squares`), verbatim and untruncated:

```
relation rms_matches_documented_mean_of_weighted_squares violated:
actual=1.0540925533463172 expected=1.3333333334015478
__consumed=i:-2|i:-4|i:4|i:1|i:-50
__rcvstate optimizer:LevenbergMarquardtOptimizer solvedCols=1
diagR=[2.23606797749979] jacNorm=[2.23606797749979] beta=[0.10557280900008412]
permutation=[0] rank=1 lmPar=0.0 lmDir=[2.0464373086829374E-10]
initialStepBoundFactor=100.0 costRelativeTolerance=1.0E-10
parRelativeTolerance=1.0E-10 orthoTolerance=1.0E-10
qrRankingThreshold=2.2250738585072014E-308
jacobian=[[2.23606797749979], [-1.0]] cols=1 rows=2
targetValues=[-2.0, -4.0] residualsWeights=[4.0, 1.0]
point=[-2.6666666668030956] objective=[-2.6666666668030956, -2.6666666668030956]
residuals=[-1.8303869531166583E-10, -1.490711984938847]
cost=1.8856180832605967 maxIterations=1000 iterations=30
```

The documented `getRMS` formula, evaluated on the fields the METHOD reads
(`residuals`, `residualsWeights`, `rows`) at this exact state:

```
sqrt( (4.0*(-1.8303869531166583e-10)^2 + 1.0*(-1.490711984938847)^2) / 2 )
  = 1.0540925533463172
```

That is the firing's `actual=`, to all seventeen printed digits. The
relation's own `expected=` recomputes the residuals from
`targetValues - objective` instead, giving `1.3333333334015478` — also
reproduced to all seventeen digits, and exactly the Qᵀ error
`docs/math65-formula-read-2026-08-10.md` §1.4 diagnosed.

So on this firing the reading is unambiguous and needs no judgement: an
implementation derived from the documentation alone, at the firing's own
state, computes what the PATCHED BUILD computed. The relation is wrong. This
is one of the six RMS convictions that `getRMS` and `optimize` being
byte-identical across the two builds already proves cannot discriminate —
and p1b turns that proof into a number the pipeline computes for itself.

### 0.2 Why this reaches the population 8.42 and 8.43 could not

8.42's shadow isolation lived behind gates 5C/6B/6C, and the Math-65
convictions ride the direction-confirmed bypass that skips all three — "the
fix never had a lane". 8.43's reroute gave them a lane and found the gates
had nothing to read (6C `None` on all 36, 5C `None` on all 36, every buggy
rate below 6B's 0.95 bar, closest 0.90595).

`reference_verdict_gate` is not behind the bypass. It is called
unconditionally on every KEPT conviction, at both doors, after `adjudicate`
returns `ok`. Whatever the bypass did upstream, this gate runs. That is the
single strongest structural argument for putting p1b's terminal here and
nowhere else.

### 0.3 The mechanism already fired once, correctly

`runs-archive/runs/diffcov_reach_20260808_233005/05_patch1-Math-65-CapGen_c`
carries the archive's only `conviction VOIDED`, on the harness-track oracle
`circle-documented-chisquare`, on the CORRECT Math-65 patch — a false alarm
prevented by exactly this comparison, at test state, where it happened to
apply. p1b is not a new idea being introduced; it is the same idea given the
input its own abstention message asks for.

## 1. The reading, mechanically

One pure function, in the shape `isolated_value_reading` already established
(`evidence_facts.py:936`): it returns a dict, never raises, never guesses.

**Inputs**
* `fired_line` — the recorded `[relfire]` line for this firing.
* `admitted` — the admission record for the firing's disputed observable
  (see §3).
* `builder`, `buggy_dir` — to compile and run the reference driver.

**Step 1 — split the line into three regions before parsing anything.**
The state printer emits `name=value` pairs on the same line as the
observables, so a `key=value` parser run over the whole line reads
`residuals=`, `cost=`, `rows=` as if the relation had observed them. Split at
the first ` __consumed=` and at the first ` __rcvstate `:

* `message` — everything before ` __consumed=`: the relation's own
  observables (`actual=`, `expected=`, or the `got …`/`was …` prose forms).
* `consumed` — the typed draw log.
* `state` — one or more ` __rcvstate <label>:<SimpleName> f=v f=v …` blocks.

This split is REQUIRED and is also a repair of an existing hazard: today's
`reference_verdict_gate` calls `observed_values(_fired)` on the whole line,
and since p1a landed that line carries state fields. No archived void is
attributable to it, but the collision is live and must be closed at the same
site.

**Step 2 — resolve the observed and claimed values from `message` only.**
* observed = the value under a non-reference key (reuse `_reference_key`,
  which already excludes `expect*` and `tol|eps|tolerance|epsilon`), or the
  `actual=/got=/was=`-tagged number (`_TAGGED_NUM_RE`), or the bare trailing
  number (`_TRAILING_NUM_RE`) — in that order, first hit wins.
* claimed = the value under the single `expect*` key, when there is exactly
  one.
* Neither resolvable → ABSTAIN (`no-observable`).

**Step 3 — map the state onto the reference's parameters** (§2). Failure at
any point → ABSTAIN with that step's own reason.

**Step 4 — evaluate.** Build a call driver with
`build_reference_call_driver(reference_class, [(key, declared)], literals)` —
the same function the admission chain already uses — and run it through
`run_reference`. Reuse of the exact driver builder matters: it already hoists
array literals into static fields to stay under the JVM's 64 KB
bytecode-per-method cap, which a Math-65 state with a few hundred points
would otherwise blow. Any compile or run failure → ABSTAIN
(`reference-unrunnable`); `run_reference` already fails closed on every path.

**Step 5 — the three-way reading.** With `R` = reference, `X` = observed,
`Y` = claimed, all compared through `_values_agree` (§4):

| condition | reading | meaning |
|---|---|---|
| `R ≈ X` and not `R ≈ Y` | `agrees-with-patched` | the relation's expected value is wrong at this state; the firing is spurious → dismissal-eligible |
| `R ≈ Y` and not `R ≈ X` | `agrees-with-check` | an independent implementation sides with the relation against the patched build → conviction corroborated |
| `R ≈ X` and `R ≈ Y` | `degenerate` | the check fired on a difference smaller than the rounding floor separates — ABSTAIN |
| neither | `mutually-inconsistent` | the reference is a third answer; nothing is established — ABSTAIN |
| any earlier failure | one of the named abstention reasons below | ABSTAIN |

Four readings, and every failure path carries its own greppable reason:
`no-reference`, `no-reference-for-this-observable`, `no-observable`,
`no-matching-receiver`, `ambiguous-receiver`, `receiver-never-ran`,
`non-finite-state`, `truncated-state`, `state-lost-in-consumed-payload`,
`parameters-not-read-by-method`, `unmappable`, `reference-unrunnable`.

The tag is `[fact:reference-at-firing-state]`, joining the existing
`[fact:…]` vocabulary. `REFERENCE_FIRING_READINGS` names the four readings;
`_REFERENCE_FIRING_DISMISSING = frozenset({'agrees-with-patched'})` — a
one-element terminal set, deliberately.

Note what `degenerate` protects. A genuine catch fires where the correct
implementation and the patched build differ, so `R ≈ X` and `R ≈ Y` cannot
both hold at a real divergence. Where both hold, the difference the relation
condemned is below the floor we call agreement everywhere else, and dismissal
would be a floor artefact rather than a finding.

## 2. State-mapping rules, one per shape in the 8.31 inventory

The mapping answers one question: for each parameter the admitted reference
declares, what Java literal do we pass? The admission chain already resolved
*which canonical state field* each parameter corresponds to
(`match_parameters` → `mapping`, a list of field names in call order). p1b
reuses that mapping unchanged. What changes is only where the field's VALUE
comes from: the twin's `__param_*` print at test state becomes the firing's
`__rcvstate` print at firing state. `java_literal(typ, printed)` converts,
exactly as it does today.

Everything below is a rule for choosing the printed value, and every failure
is an abstention with its own greppable reason.

### 2.1 Two receivers in one firing (`opt1:` / `opt2:`)

The 8.31 corpus showed a firing whose check constructed two receivers
(`opt1:` and `opt2:`), both captured, both printed. Measured across the
archive the shape is commoner than that: `diffcov_reach/01`'s Chart-19 firing
carries THREE blocks in one line — `__rcvstate domainAxis:CategoryAxis …
__rcvstate baseAxis:NumberAxis … __rcvstate plot:CategoryPlot …`. The line
does not say which receiver the observed value came from, and guessing is the
class of silent-wrong-input error `match_parameters` was hardened against.

Rule, in order:

1. **Type filter.** Keep only receivers whose printed `SimpleName` is the
   declaring type of the disputed method or a name reachable from it by the
   subtype closure the pipeline already computes for diff headers. If exactly
   one survives, use it.
2. **Field-cover filter.** Of the survivors, keep only those printing every
   field in `mapping`. If exactly one survives, use it.
3. **Evaluate-both.** If two or more survive, evaluate the reference at each.
   If every candidate yields the same `R` under `_values_agree`, the ambiguity
   is immaterial — use it. If they differ, ABSTAIN
   (`ambiguous-receiver`).
4. No receiver survives → ABSTAIN (`no-matching-receiver`).

Rule 3 is the one that earns its place: it converts an ambiguity into a
measurement instead of into a heuristic, at the cost of one extra JVM run in
a case that is rare by measurement.

### 2.2 Uninitialised receivers — the 8.31 abstain rule, kept byte-for-byte

8.31 recorded that 2 of Math-65's 3 corpus firings fired on an optimizer that
NEVER RAN, and took the design answer: such a firing carries no state at
which the reference can be evaluated, so p1b classifies it ABSTAIN. That
decision stands here unchanged. The corpus line, verbatim
(`mechp1b_20260808_215154/01`):

```
__rcvstate opt:LevenbergMarquardtOptimizer solvedCols=0 diagR=null
jacNorm=null beta=null permutation=null rank=0 lmPar=0.0 lmDir=null
… jacobian=null cols=0 rows=1 targetValues=null residualsWeights=[0.01]
point=null objective=null residuals=[-1000.0] cost=0.0
maxIterations=1000 iterations=0
```

**The obvious implementation of the rule does not work on this line, and that
is why the rule needs its own predicate.** `java_literal` already returns
`None` for a printed `null`, so any MAPPED field printing `null` abstains for
free. But a reference whose parameters are `(residuals, residualsWeights,
rows)` maps onto three fields that are all non-null here — `[-1000.0]`,
`[0.01]`, `1` — so it would evaluate cleanly and return a confident number
computed from a state the optimizer never produced.

So the predicate looks at the WHOLE chosen receiver, not the mapped subset:

> `receiver_never_ran(state_block)` = a field whose name matches
> `iterations|iterationCount|evaluations|evaluationCount` prints `0`, AND at
> least one reference-typed field of that receiver prints `null`.

On the line above: `iterations=0` and `jacobian=null` → ABSTAIN, reason
`receiver-never-ran`. This is exactly 8.31's "mechanically detectable:
null/zero sentinel fields", read off the whole object. The inherited
`java_literal` rule stays as the second layer.

8.31 also left a question open — whether these firings deserve treatment
BEYOND abstention, as a distinct alarm kind ("contract violated at
construction" rather than "at computation"). This design does not answer it.
It records the class, counts it, and acts on nothing. Anything else would be
a new dismissal path validated on n≈2.

### 2.3 NaN and the uncomputed cache

8.31 found, verbatim in `mechp1b_20260808_215154/02`,
`__rcvstate dist:HypergeometricDistribution numberOfSuccesses=423253
populationSize=683894 sampleSize=13108 numericalVariance=NaN
numericalVarianceIsCalculated=false` — a lazily-computed cache that has not
been computed, not a corrupted value. Feeding NaN to the reference produces
NaN, and `_vals_match` treats NaN==NaN as agreement, so an uncomputed cache
could manufacture an `agrees-with-patched` dismissal out of two blanks.

Rule: **any mapped field whose printed value is `NaN`, `Infinity` or
`-Infinity`, or whose printed array contains one, ABSTAINS**
(`non-finite-state`). No exception, no companion-flag cleverness. The
companion boolean (`<name>IsCalculated`/`<name>Computed` = `false`) is
RECORDED in the fact's detail so the class stays countable, but it does not
gate anything: the plain non-finite rule already covers it and is impossible
to get subtly wrong.

This is stricter than the pipeline's own arithmetic elsewhere, deliberately.
A non-finite input is the one case where the comparison's own agreement
semantics point the wrong way.

### 2.4 Truncation

Several caps can cut a value: the state printer's 400 chars per field and
3000-char total, `harvest_relfire_lines`' 6000-char window, and the trace
recorder's 300-char display cap. 8.31 fixed the *only-copy* problem
(result.jsonl now holds the untruncated line at both persistence sites) but
not the caps themselves.

**Truncation carries no marker.** A sweep of every archived `[relfire]` line
found zero `…` or `...` terminators — a cut line simply stops. The corpus
shows both kinds, verbatim: mid-array
(`objective=[-3.2010762339444594, -3.201`) and mid-token
(`permutation=nul`). Detection must therefore be structural, not
marker-based.

Rule: a mapped field's printed value is USABLE only if it is
self-terminating — a scalar token followed by whitespace or end-of-block, or
a bracketed form whose brackets balance and which ends in `]`. Otherwise
ABSTAIN (`truncated-state`). The same test applies to the `__rcvstate` block
as a whole: if the line ends inside a field's value, that field is dropped,
and if it is mapped, abstain.

**Mask `__consumed` before any bracket-balance test.** The consumed log
carries quoted string payloads (`q:"…"`) containing raw bytes — literal `]`,
`"`, and control characters drawn by the fuzzer. Counting brackets across
them produces false truncation readings; a coverage sweep hit exactly that on
one row and had to mask the payload to get the right answer. The §1 three-way
split does most of this work; the bracket test runs on the `state` region
only.

Those same raw bytes are a real corruption source, not merely a parsing
nuisance: one archived conviction (`stack_confirm/02`,
`categoryplot-range-axis-index-null-always-illegal`) has all five recorded
copies cut inside a `q:"` payload, before `__rcvstate` would have appeared.
Detection is simple — `__consumed` present, `__rcvstate` marker absent →
ABSTAIN, reason `state-lost-in-consumed-payload`. (The recording-side repair,
escaping control characters inside `RecFDP.rec`'s string branch, is a p1a
change and is noted here rather than proposed.)

A truncated array must never be silently shortened. A shorter array changes
`rows`, changes the sum, and produces a confident wrong number — the worst
available failure.

### 2.5 Typed consumed labels

`__consumed` now carries type tags (`i:`, `d:`, `q:"…"`, `ia:[…]`, …) in
consumption order. It is tempting to fill an unmapped parameter from it.

Rule for v1: **`__consumed` never supplies a parameter.** It is used for
exactly two things:

1. **Recorded** verbatim in the fact's detail, so a human reading the trace
   can reconstruct the firing without the artifact.
2. **A cross-check, one direction only.** If a scalar parameter recovered
   from `__rcvstate` has a value that appears among the consumed draws with a
   compatible type tag, record `consumed-consistent`. If the parameter's
   value appears nowhere and no consumed entry of that type exists at all,
   record `consumed-silent`. Neither changes the reading.

The reason is the roll-8 finding this codebase already paid for: positional
type matching fed a reference two same-typed arrays in the wrong order —
"same type, same length, runs cleanly, computes garbage". `__rcvstate` gives
us named fields and `match_parameters` gives us a name-resolved mapping;
`__consumed` gives us an ordered list of untyped-by-role values. Using the
second where the first is missing trades a named binding for a positional
guess, which is the trade the mapper exists to refuse.

If a later corpus shows a real population of firings that map only through
`__consumed`, that is a separate design with its own gate.

### 2.6 Where the state comes from, and what it is state OF

`replay_on_patched` compiles the check against the PATCHED build
(`relation_screen.py:1011`, `record_firings=True`), so a replay-track
conviction's `__rcvstate` is the PATCHED build's receiver at the moment the
relation fired. That is the right state and the right build: the question p1b
asks is "at the state where this check condemned the patched build, does an
independent implementation condemn it too?".

The harness track's firings come from the fuzz harness, which does not carry
the recording wrapper. Harness-track firings will therefore have no
`__rcvstate` and abstain by reach, exactly as they do today. Extending the
recorder to the harness template is the natural next increment and is NOT
part of this design.

A second reach limit, already measured: a check that constructs nothing
capturable emits no state at all. `capture_receivers` anchors on
`var = new <Type>(…)`, so the Lang-50 conviction — which calls static
`DateFormat` factory methods and holds no receiver — records a complete,
untruncated firing line with `__consumed=i:0|i:0` and no `__rcvstate`
whatever. That is the stateless-receiver ceiling 8.27 named, reappearing as a
p1b coverage limit. It abstains, correctly, and 8.27 remains its named
candidate fix.

### 2.7 The parameters must be ones the method actually reads

This is the rule the Math-65 desk read implies and did not state as a gate.
Its 2×2 table carries a column "Reads what the method reads?", and every
wrong relation answers NO — they recompute residuals from
`targetValues − objective` while `getChiSquare` reads the stored `residuals`
field, which `LevenbergMarquardtOptimizer` has overwritten with `Qᵀ·r`.

The same trap is available to the REFERENCE. A generated reference declaring
`compute_getChiSquare(double[] residuals, double[] residualsWeights, int
rows)` maps onto the fields the method reads and reproduces the patched
build. One declaring `compute_getChiSquare(double[] targetValues, double[]
objective, double[] residualsWeights)` maps onto three real canonical fields
too — and computes the relation's answer instead. Same state, opposite
verdict.

Rule: **every field in `mapping` must appear in
`fields_read_by(class_context, method, canonical)`** — the read-order list
the admission chain already computes from the buggy method's own body.
Otherwise ABSTAIN, reason `parameters-not-read-by-method`.

This is legitimate authority by the codebase's own standing: `fields_read_by`
reads the buggy implementation, which is rank 2 and is OUR deterministic code
doing the reading; the generator never sees it, and `ImplementationLeak`
enforces that. Knowing which fields a computation consumes is not knowing how
it computes them.

Note the check is cheap and it is a screen the ADMISSION chain could also
apply. It is placed here because p1b is where a wrong binding turns into a
verdict.

## 3. Where the reference comes from — and the single-slot defect

The reference is never generated by p1b. p1b consumes an ALREADY-ADMITTED
one: generated blind to both implementations (`ImplementationLeak` enforces
it), screened against the buggy build on ≥3 shared sibling observables
(`screen_reference`), corroboration-attributed, and pin-checked against the
failing test's own answer (`pin_check`). If any of those said no, there is no
reference and p1b abstains. The gate consumes admission; it never
manufactures it.

**The defect that must be fixed first.** `run.py` stores admission as

```python
_reference_impl_fact._admitted = {'method': method, 'obs': obs, 'buggy': buggy_obs}
```

— a single attribute, overwritten by each successful attempt. Measured
consequence in the archive: `stack_confirm/05` admitted three references
(`getChiSquare`, `getPointRef`, `getValueRef`) and kept only the last;
`mechb/09` admitted three and kept only the last. The gate then compares a
chi-square firing against a `getPoint` reference and abstains on "no shared
observable" — 36 of the archive's 221 abstentions carry exactly that reason.

p1b requires:

* `_admitted_by_method`, a dict keyed by `observable_key(method)`, every
  admission retained;
* each record carrying what re-evaluation needs — `src` (the reference
  source), `sig` (declared signature), `mapping` (parameter → canonical field
  names, in call order), `matched` (canonical → declared observable names),
  `ref_dir` (the compiled classes directory, so the reference is compiled
  once per leg and only the driver is rebuilt per firing), `screen_why` and
  the screened-sibling count for the fact's standing sentence.

Lookup at gate time is by the firing's disputed observable, resolved with the
existing `disputed_observables(fired, ctx, check_source=…)` and normalised
through `observable_key`. **No record for that observable → ABSTAIN
(`no-reference-for-this-observable`).** Substituting a reference for a
*different* observable is not a fallback; it is the current bug.

This matters concretely for the referee (§5): across the archive, no leg ever
admitted a `getRMS` reference, and every Chart-19 leg that admitted anything
admitted `getLowerMargin` — an observable unrelated to the
`getRangeAxisIndex` / `indexOf` convictions. Honest lookup turns those into
abstentions instead of into wrong readings.

## 4. Tolerance and normalisation — reused, not reinvented

Nothing new is calibrated. p1b uses:

| need | reused from |
|---|---|
| scalar agreement | `reference_impl._values_agree` → `evidence_facts._close(a, b, rel=1e-9)`, the rounding floor `|a−b| ≤ rel·max(1,|a|,|b|)` |
| array agreement | `reference_impl._arrays_agree` — bracket/comma skeleton exact, elements at the floor (the one-ulp asymmetric-covariance lesson) |
| escaped text | `_decode_java_literal` on both sides (9.1b, the fourth escape-blind comparator) |
| observable naming | `reference_run.observable_key` (`chiSquare` ≡ `getChiSquare`) |
| weak differences | `reference_impl.WEAK_KINDS` — a `value_ulp` difference IS agreement |
| reference-vs-observation keys | `evidence_facts._reference_key` (`expect*`, `tol|eps|tolerance|epsilon`) |
| number extraction from prose messages | `evidence_facts._TAGGED_NUM_RE`, `_TRAILING_NUM_RE` |
| non-finite handling | `evidence_facts._finite`, applied as §2.3's abstain rather than as a comparison |

One consequence worth stating: because agreement is the floor rather than
exact equality, `agrees-with-patched` does not require the reference to
reproduce the patched build bit-for-bit. On the §0.1 exemplar it does anyway,
to seventeen digits, which is what makes that case an exemplar rather than a
tolerance argument.

## 5. Where the fact enters, and the narrowest terminal use

### 5.1 Two entry points, one of them terminal

**(a) Evidence — always, both readings, as a computed fact.** The fact block
is appended to `_fact_notes` / `_evid` at both judge doors, in the same
computed-fact wording the codebase already uses: what was computed, at what
state, and what it says. No dismissal instruction, no keep instruction. The
judge decides what it decides. This is auditability, not persuasion — roll 12
measured nine deliveries of the reference fact and zero engagements, and the
user's decision then was to stop persuading. The fact is in the evidence so a
human reading the trace can see the arithmetic, and for nothing else.

**(b) `reference_verdict_gate` — terminal on exactly one reading.**
`agrees-with-patched` returns `'void'`. Everything else returns `'abstain'`
with its reason. That is the whole terminal surface.

### 5.2 Why that is the narrowest terminal use available

Four properties, each structural rather than argued:

1. **It can only void a keep, never manufacture one.** The gate is called
   inside `if ok:`, after `adjudicate` has already decided to keep. The
   38-row correct-dismissals guard — the population that guards
   keep-pushing mechanisms — is untouched by construction, and
   `tests/test_reference_statetwin.py` already pins that structural property
   (`test_gate_runs_only_on_kept_convictions_and_before_the_keep`).
2. **`agrees-with-check` (corroborate) is therefore ADVISORY, and must be.**
   It is the direction that pushes toward accusation, so it is the direction
   that can create a false alarm. At this site it also cannot do anything —
   the finding is already kept. Making it a fact and not a verdict costs
   nothing and closes the only route by which p1b could add a conviction.
   This reverses nothing in 8.4x's original sketch: that note wanted
   "sides-with-relation → CORROBORATED", and corroborated is what the fact
   says. It just does not become a verdict.
3. **It touches no LLM judgement.** No family-duty escape, no re-ask, no
   prompt change. 8.43's lost catch (varbase/10) was lost to a terminal whose
   only defence was an LLM answer that came back wrong once in three; p1b's
   terminal has no such component. Its defence is arithmetic, and its failure
   mode is abstention.
4. **It is not on the 5C/6B/6C ladder and must not be put there.** Those
   gates share one family-duty answer and each of them can drop. Adding a
   fourth is adding a fourth chance to drop a genuine catch. The whole point
   of the placement is that this gate already exists, already runs after the
   keep, and already abstains on everything it cannot prove.

### 5.3 What is explicitly NOT done

* No change to `direction_confirmed_bypass`. `REROUTE_INDISCRIMINATE_BYPASS`
  stays OFF (8.43's action). p1b does not need it.
* No judge or verifier prompt change.
* No new dismissal reachable from a failed measurement — every failure path
  returns `'abstain'`, which is today's behaviour byte-for-byte.
* No screen-time change. Relation soundness at invention time is a different
  mechanism (8.42's option (c)) and stays separate.

## 7. Validation plan

Gates written before the build, per house rule. Rule 7 applies: two
iterations with no change → stop and report.

### G-P1 — offline, zero LLM: the exemplar
Replay the §0.1 firing through the mapping and the reading with a STUBBED
reference (the documented `getRMS` formula in Python, standing in for the
generated Java) and assert the reading is `agrees-with-patched` and the
computed `R` equals `1.0540925533463172`. This pins the parser, the split,
the field mapping and the three-way logic without a JVM. Fail → the design is
wrong on the one case we verified by hand.

### G-P2 — offline, zero LLM: the shape rules
Each 8.31 shape gets a row built from the corpus's own recorded lines, not
from invented fixtures:
* two receivers, same reference value → reading proceeds;
* two receivers, different reference values → `ambiguous-receiver` abstain;
* uninitialised receiver → `receiver-never-ran` abstain;
* NaN with `…IsCalculated=false` → `non-finite-state` abstain;
* mid-array truncation → `truncated-state` abstain, and the array is NOT
  shortened;
* state fields present → the observable parser sees `actual`/`expected` and
  NOT `residuals`/`cost`/`rows`.

### G-P3 — offline: no genuine catch is dismissable
For every row of the 67-row genuine-catch guard and every archived TP
conviction, the reading must not be `agrees-with-patched`. Rows with no
reference read `no-reference` and are reported AS an abstention-by-reach
result, not as an exoneration — the same disclosure
`test_gate_voids_nothing_on_the_genuine_catch_population` already makes.
**Referee B is the named member of this gate.** One dismissal here =
redesign, not a threshold change.

### G-P4 — offline: fail-closed on every failure path
Inject, one at a time: a compile failure, a driver timeout, an unparseable
state block, a `null` mapped field, a truncated array, a NaN, an absent
admitted record. Each must yield `'abstain'` and leave the verdict
byte-for-byte identical to today's. This is 8.39's lesson restated: prove the
guard was ACTIVE, not merely silent.

### G-P5 — the archived four
Run the full chain (real JVM, real reference source recovered from the
archived trace) on the 4 rows §6.3 identifies: `stack_confirm/04`,
`stack_confirm/05`, `stack_confirm/06`, `gs1_isolation/03`. Prediction,
pre-registered: all 4 read `agrees-with-patched`, including the two Family B
rows. Any `agrees-with-check` → redesign per §6.1.

A fifth row, `stack_confirm/06`'s RMS conviction, is run as an ORACLE rather
than a gate: with a hand-supplied `getRMS` reference standing in for an
admitted one, the reading must be `agrees-with-patched` and `R` must equal
`1.0540925533463172`. It does not count toward the gate — the reference was
not admitted by the pipeline — but a failure there means the mapping is
wrong, because §0.1 already computed the answer.

### G-P6 — live roll shape (for the 32 that offline cannot reach)
Because §6.3's binding constraint is admission and not recording, the live
roll must be designed to produce admissions, not merely to observe:
* **Arm 1 — the target.** Math-65-c ×3 at `-n 5 -m 12 --reference_impl`, the
  same flags as `varbase`/`mechb`/`stack` so the numbers stay comparable.
  Read: per firing, was a same-observable reference admitted, did the state

* **Arm 2 — the safety arm.** Chart-19-o ×3 and one further overfit leg, same

* **Arm 3 — held out.** After arms 1–2 pass, one 3-arm roll on bugs used

deletes them.

### G-P7 — suite and scope
Full pytest green. No judge or verifier prompt touched. No cross-run pooling
— the reference, the driver and the reading are built from THIS run's own
admitted reference and THIS run's own recorded firing, and are discarded at

## 8. Risks

### 8.1 Reference quality and, above it, reference COVERAGE

The design assumes the admitted reference is right. Admission is a real
screen — ≥3 shared sibling observables against the buggy build, corroboration
attribution, and a pin check against the failing test's own answer — and its
one structural blind spot (a bug-copying reference agrees with buggy
everywhere including the defect) is exactly what the pin check exists to
catch. That is as good as it gets without a second independent
implementation.

But the measured risk is not quality; it is **coverage**, and it is the
largest risk in this design by a wide margin. §6.3: 4 of 36. 166 of the
archive's 221 gate abstentions read "no admitted reference for this leg". No
`getRMS` reference has ever been admitted. Chart-19 admits only
`getLowerMargin`. A mechanism that abstains 31 times out of 36 is not wrong,
but it is not yet a mechanism either.

The single-slot defect (§3) is a real contributor and is cheap to fix: three
legs in the archive admitted a `getChiSquare` reference and then overwrote it
with a `getPointRef` one. Fixing that alone moves rows from "no shared
observable" into reach. Beyond it, the coverage question belongs to the
generation and screening side — `too_thin_to_screen`, the sibling count bar,
`extract_test_setup`, the signature-mapping discards 8.28(a) read — and it is
the work that decides whether p1b is worth building at scale. **A defensible
sequencing is: fix the admission store, measure admission coverage on one
live roll, and only then build the gate.** This design does not force that
order, but it names it as the honest one.

### 8.2 Stateful mapping brittleness

The mapping is a chain — `disputed_observables` → admitted record →
`match_parameters`' field names → the `__rcvstate` block → `java_literal` —
and each link has failed before in a way that compiled and ran. The
mitigations are: no link may guess (every unresolved link abstains with its
own reason); the parameter→field mapping is REUSED from admission rather than
recomputed at the gate, so the gate cannot disagree with the screen about
what the reference's arguments mean; and the §2 rules are conservative in one
direction only.

**The sharpest residual risk, named: the reference's own parameter choice
decides the answer.** On Math-65 the two plausible bindings give opposite
verdicts — `(residuals, residualsWeights, rows)` reproduces the patched
build and reads `agrees-with-patched`; `(targetValues, objective,
residualsWeights)` reproduces the relation and reads `agrees-with-check`.
Both map onto real canonical fields. §2.7's rule is the mitigation and it is
a real one, because the second binding names fields `getChiSquare`'s body
does not read. But it is a rule about a generated artifact, so it is a rule
that can be evaded by a reference that happens to name the right fields and
compute the wrong thing.

What makes this survivable is the asymmetric terminal (§5.2). The failure
mode is a spurious `agrees-with-check`, and `agrees-with-check` is advisory —
it records a fact and changes no verdict. A wrong binding costs a misleading
sentence in a trace, not a wrong dismissal. This is the clearest single
payoff of refusing to make the corroborate side terminal, and it is why that
refusal should not be revisited without a separate measurement.

The other residual that no rule removes: a mapping that is wrong but
consistent — right types, right lengths, wrong fields — produces a confident
number in the dismissing direction. §6.1's referee is aimed exactly at it: on
Math-65 we already know the right answer by hand, so a wrong mapping shows up
as `agrees-with-check` or `mutually-inconsistent` rather than as a silent
success.

A second residual: the receiver captured by `capture_receivers` is the
LOCALLY CONSTRUCTED object, and a check that mutates it between construction
and the firing prints the mutated state — which is correct — but a check that
fires on a DERIVED object it did not construct (a returned optimum, a cloned
plot) captures the constructor's receiver and not the observed one. §2.1's
field-cover filter catches the common case; the uncommon case abstains as
`no-matching-receiver`. It cannot produce a wrong reading, only a missing one.

### 8.3 Cost

One javac plus one JVM run per gated firing, bounded by admission (about 10%
of firings historically) and by the reference being compiled once per leg —
only the driver is rebuilt. §2.1's evaluate-both rule doubles that in a rare
case. This is the same cost envelope 8.4x pre-registered and it is not the
binding constraint.

### 8.4 The abstention rate reads as safety and hides inertness

221 abstentions and 1 void is a mechanism that is nearly always silent. The
counter is the per-event read-out and the 8.39 lesson: every gate entry
records WHICH abstention reason applied, so "the guard was active and found
nothing" is distinguishable from "the guard never had an input". Without
that, a p1b that is completely broken and a p1b that is completely safe
produce identical traces.

## 9. The fallback design — the AST family-duty fact

Recorded here as the named alternative, sketched only, in case §8.1's
coverage risk makes the reference route unaffordable.

**The failure it repairs.** 8.43's G-B2: `varbase/10`'s only conviction was
killed by the 6B terminal on family-duty NO, kept 1 of 3 repeats; the
identically-shaped `varbase/12` survived 3 of 3 on family-duty YES. Same bug,
same failing test, same 100% buggy rate. The saving distinction is an LLM
judgement, and the judgement's stated reason was that the check "additionally
requires the same on a separate fresh plot", i.e. it asserts a SUPERSET of
the test's observable. A superset of the pinned observable is not a different
observable.

**The fact to compute instead.** Family duty asks: is the property this
firing violated the failing test's own observable? That is answerable
structurally.

1. From the check's source, extract the call under the assertion that
   THREW — the receiver expression's static type, the method name, the
   argument arity, and whether the assertion is an expected-throw or a
   value comparison.
2. From the failing test's source, extract the same tuple for every
   assertion and every `try`/`fail()` expected-throw.
3. `family-duty-mechanical = YES` when some test assertion shares
   (declaring type, method name, arity, assertion kind) with the check's
   throwing call. `NO` when the check's method name appears nowhere in the
   test's assertions. `UNDETERMINED` otherwise — and undetermined falls
   through to today's LLM answer, unchanged.

On varbase/10 this reads YES: the check's throwing call is
`CategoryPlot.getRangeAxisIndex(null)` under an expected-throw assertion, and
so is the test's. The extra fresh-plot probe adds a receiver STATE, not an
observable, and state is not part of the tuple — which is precisely the
distinction the LLM got wrong.

**Why it is a fallback and not the plan.** It is a syntactic matcher, and
8.28/9.2 both record what this codebase now calls the fingerprint of a
matcher that cannot fail — a perfect score. It would need its own control
(how often does the tuple match on checks that are NOT family-dutiful?)
before it could be terminal anywhere, and it would need to be
`UNDETERMINED`-heavy by design. It is also orthogonal: it protects catches
from the 6B terminal, while p1b dismisses false convictions. If both are
built, the AST fact should land first, because it is the one that repairs a
measured loss.

## 11. ADDENDUM — step 1 built: the admission store (2026-08-11, Mac only)

Step 1 of the approved p1b sequence: the §3 prerequisite only. No gate logic,
no firing-state reading, no new dismissal path, no VM, no commit. The full
suite is green at `1013 passed, 7 skipped` (baseline 1005 passed, 7 skipped;
the 8 new tests are the difference).

### 11.1 What was built

**`src/java/relations/reference_impl.py`** — three new pure functions and one
additive parameter:

* `admission_key(method)` — the store slot for an observable name; it is just
  `reference_run.observable_key`, so `chiSquare` and `getChiSquare` are one
  slot exactly as everywhere else in the pipeline.
* `admit_reference(store, method, record) -> (stored, why)` — inserts under
  the observable the reference is FOR. `SAME_OBSERVABLE_RULE = 'keep-first'`.
* `admitted_reference_for(store, fired, ctx, check_source=None) ->
  (record_or_None, why)` — resolves the firing's own disputed observables with
  the chain's own `disputed_observables`, normalises through `admission_key`,
  and returns the first record that matches. Miss →
  `no-reference-for-this-observable` in the reason, verbatim and greppable.
* `reference_verdict_gate(fired_msg, admitted, lookup_why=None)` — the third
  parameter is additive and is used ONLY where there is no record to read, so
  the abstention says which observable went unmatched instead of the flat "no
  admitted reference for this leg". Called with two positional arguments the
  gate is unchanged, byte for byte.

**`src/java/run.py`**

* `_reference_impl_fact._admitted` (one slot, overwritten) is GONE.
  `_reference_impl_fact._admitted_by_method` (dict) replaces it, initialised
  beside `_memo` with the same lifetime argument: one process = one leg, so
  the store is run-local by construction and nothing pools across runs.
* Each admission now stores a record carrying `method`, `obs`, `buggy`, `src`,
  `sig`, `mapping`, `matched`, `screen_why`, `screened`, `siblings`,
  `fields_read`, `reads_what_method_reads`, `ref_dir` (see 11.4).
* A new deterministic event per admission, naming the observable:
  `admission STORED for observable \`<key>\`` or `admission SET ASIDE —
  duplicate observable (keep-first)`, with the store's full key list, the
  parameter→field `mapping`, and the §2.7 material in its detail.
* A new `_admitted_for(fired, class_ctx, check_src)` helper does the lookup
  and records a `reference-admission-lookup` event at EVERY call. Both judge
  doors use it with their own firing and their own check source; each passes
  the resolved record and the lookup reason into the gate.

### 11.2 The same-observable rule, and why keep-first

**Keep-first.** A second reference admitted for an observable that already has
one is set aside, with its reason recorded; the incumbent is never displaced.

Three reasons, none of them taste:

1. **Admission is binary, so "best" would have to be invented.** A record is
   in the store only because it passed the screen (≥3 shared sibling
   observables reproduced against the buggy build), the corroboration
   attribution and the pin check. Nothing the chain computes ORDERS two
   references that all passed. Ranking by screened-sibling count or by
   anything else would be a preference the screen does not express, applied to
   decide which implementation gets to void a conviction.
2. **Keep-first makes the store append-only.** A record never changes after it
   is written. The gate runs at BOTH doors, interleaved with further
   admissions, so under keep-last the same firing could read a different
   reference depending on WHEN it looked — a wrong answer that depends on door
   ordering is the hardest kind to see in a trace.
3. **The first admission is already the highest-ranked candidate.**
   `disputed_observables` ranks candidates by signal strength and the chain
   attempts them in that order, so overwriting the first with a later one is
   the single-slot defect in miniature.

### 11.3 The one back-compat pass-through, recorded rather than hidden

`admitted_reference_for` returns the leg's ONE admitted record even when the
lookup misses, provided the store holds exactly one record, and says
`SUBSTITUTED` in its reason. That is byte-for-byte what the single slot did,
which keeps step 1 a pure repair of the RETENTION defect: every archived
single-admission leg reads exactly as it did before, so the step-2 coverage
roll measures admissions and not a changed gate.

With two or more records the pass-through does not apply and the miss is an
honest `no-reference-for-this-observable` — §3's rule, in the only place where
the old behaviour was already indefensible (it is the shape that produced 36
of the archive's 221 "no shared observable" abstentions).

**The step-3 gate build removes the pass-through**, at which point the miss is
always `no-reference-for-this-observable` and it is one of §1's named
abstention reasons.

### 11.4 What was deliberately NOT built

* **`ref_dir` is `None`.** `run_reference` compiles the reference and does not
  return the compiled classes directory. Plumbing it out is a signature change
  to a JVM-facing function with no consumer until the gate exists, so the key
  is present and empty. **Step 3 must plumb it**, or the reference recompiles
  once per firing instead of once per leg (§8.3's cost envelope assumes the
  latter).
* **§2.7 is recorded, not enforced.** The design places the "parameters must be
  fields the method actually reads" rule at the GATE — "it is placed here
  because p1b is where a wrong binding turns into a verdict" — and applying it
  as an admission screen would change which admissions exist, i.e. would
  change what step 2 measures. So each record carries `fields_read` (the
  read-order list from `fields_read_by` on the buggy method's own body) and a
  precomputed `reads_what_method_reads`: `True`/`False`, or `None` when the
  body is not visible, which is undetermined and never a failure.
* No change to `reference_verdict_gate`'s reading, to the 5C/6B/6C ladder, to
  any prompt, or to `direction_confirmed_bypass`.

### 11.5 What the step-2 coverage roll must read

Everything below is now emitted through the trace recorder (never `print()`),
so it survives into the one-file `trace.md`.

| what to count | where it comes from |
|---|---|
| admissions per leg, and for WHICH observable | `reference-impl` events with output `admission STORED for observable \`<key>\`` — the detail's `admitted_observables` is the running key list |
| references LOST to the old single slot | `admission SET ASIDE — duplicate observable (keep-first)` events; each one is a reference the old store would also have kept, but by displacing the incumbent |
| per firing: was a same-observable reference found | `reference-admission-lookup` events — output `admitted reference found` vs `no admitted reference for this firing`, detail `admitted` (the store's keys) and `used` (the record's method) |
| the honest-lookup gap | lookup reasons containing `SUBSTITUTED` — every one is a firing that today reads a reference for a DIFFERENT observable and under step 3 will abstain |
| legs with no reference at all | lookup reason exactly `no admitted reference for this leg` |
| §2.7 reach, without gating on it | admission event detail `reads_what_method_reads` (`True`/`False`/`None`) beside `mapping` and `fields_read` |
| whether §6.3's headline moves | the intersection the design counted by hand: legs where some conviction's disputed observable has a stored record AND that firing carries a mappable `__rcvstate` |

The pre-registered read for step 2 is §6.3's own number: **4 of 36 evaluable as
the archive stands, and the binding constraint is admission, not recording.**
The roll's job is to say what that number becomes on a live leg once several
references per leg survive — if it does not move, §8.1's coverage risk is the
finding and the gate build is not yet worth its cost.
