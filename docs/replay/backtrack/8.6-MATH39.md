# 8.6 — Math-39 event-chain read

**Question:** is Math-39's new 2-for-2 accusation record a named mechanism, or
documented judge-lottery? (Repair already ruled out by attempt-tag grep.)

**Source:** archived pricing-pair traces, both rolls, all accusing verdicts.
Table recorded before interpretation.

## The chains

Five accusing verdicts across the two rolls. Four assert the same property:

> the integrator must not call `computeDerivatives` at any `t` beyond
> `FastMath.nextAfter(end, Double.POSITIVE_INFINITY)`

Facts delivered on **every** one: `[trigger-test lift]`, `[buggy-replay fact]`.
Citations on **every** one: `NONE`.

The fifth (`integrate_sets_time_to_target`) asserts that after a successful
`integrate(ode, end)` the stateful ODE's recorded time equals `end` exactly.

## What the verdicts claim, and whether it is true

Each accusation invokes the failing test's authority — "the project's own
regression test explicitly requires", "the trusted regression test". That is a
**tier-1 authority claim** (the strongest tier), asserted with no quote.

**The claim is TRUE.** `DormandPrince853IntegratorTest::testTooLargeFirstStep`
pins exactly that property, inside its ODE callback:

```java
public void computeDerivatives(double t, double[] y, double[] yDot) {
    Assert.assertTrue(t >= FastMath.nextAfter(start, Double.NEGATIVE_INFINITY));
    Assert.assertTrue(t <= FastMath.nextAfter(end,   Double.POSITIVE_INFINITY));
```

So this is **not** a misremembered contract. It is not the Math-65 class.

## And the harness does not generalise the setup either

The obvious next hypothesis — the check lifts a test-specific property and applies
it to fuzzed parameters where it is not a valid contract — is also **false here**.
The harness reproduces the test's setup exactly:

```java
new DormandPrince853Integrator(0, Double.POSITIVE_INFINITY, Double.NaN, Double.NaN)
setStepSizeControl(0, 1.0, 1.0e-6, 1.0e-8)
double start = 0.0;  double end = 0.001;
```

Fuzzed: only `consumeBoolean()` and `consumeInt(1, 1000)`.

## The mechanism

A check that replays the failing test's **own pinned property at the test's own
setup**, differing only in one fuzzed dimension, fires on a patch where **the real
test passes**.

The deciding fact is therefore "the real failing test passes on this build" — and
that fact **was delivered**, in the `[trigger-test lift]` note present on every one
of these chains. The reviewer read the lift provenance as *corroboration* of the
accusation ("this is the trusted regression test's own requirement") rather than as
the scope limit it is.

## Verdict: named mechanism, NOT judge-lottery

Math-39 is a **sixth bucket-(a) case** — deciding fact collected, delivered, and
not binding — joining the five from Phase 1a. It is systematic, which is why it
repeats, and it does not belong on a "watch list" pending more observation.

**Consequences:**

1. Math-39 joins the named residual list (Closure-62, Math-30, Math-65) as a
   fourth. The 8.10 PASS bar's "historically clean legs" set loses Math-39.
2. It **strengthens** the ceiling finding rather than complicating it: bucket (a)
   is now 6 of 8 decisive cases, and the newest member fails in a way where the
   authority claim was *correct* and the evidence *was* present.
3. It sharpens 8.15's hypothesis in a specific way. Math-39 shows that classifying
   by *which authority is invoked* would NOT separate it — the accusation invokes
   tier 1 and is entitled to. What distinguishes it is **scope**: the authority is
   real but does not extend to the firing. 8.15 should test authority-tier AND
   authority-scope, or it will score this case as legitimately grounded.
