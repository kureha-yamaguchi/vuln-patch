Run as pre-registered. Raw committed before scoring (commits `b20a56a`,

## Step 1 — pre-launch

**1(a) probe: PASS.** The gpt-5.5 deployment exists, answers, and emits
`VERDICT:` first — the format the parser assumes.

**1(b): found and fixed a real hole** (`docs/replay/backtrack/8.1-STEP1B.md`).
Two producers used `why or "<sentinel>"`, which suppressed the fail-open

read as a *usable verdict*. Model-swap sensitive: manufactured verdicts would

## Part A — per-case flips (the pre-registered read-out)

```
  incumbent draw0 vs draw1 (FLOOR) :  21 / 228 =  9.2%
  gpt-5.5 vs incumbent draw0       :  23 / 228 = 10.1%
  gpt-5.5 vs incumbent draw1       :  32 / 228 = 14.0%
```

**On the pre-registered criterion the flip RATE is at the floor.** 10.1% against
9.2% is not signal.

**But the flip DIRECTION is not noise.** This is the finding:

```
  incumbent draw0 -> draw1 (FLOOR)   drop->keep   8 | keep->drop  13 | net   -5
  incumbent draw1 -> draw0 (FLOOR)   drop->keep  13 | keep->drop   8 | net   +5
  incumbent draw0 -> gpt-5.5         drop->keep  21 | keep->drop   2 | net  +19
  incumbent draw1 -> gpt-5.5         drop->keep  28 | keep->drop   4 | net  +24

  two-sided sign test, gpt-5.5 flips 21 vs 2: p = 0.0001
  same test on the FLOOR             8 vs 13: p = 0.3833
```

The floor's disagreements are balanced, as noise should be. gpt-5.5's are
overwhelmingly one-directional: **it dismisses less.**

### What that buys and costs

```
                     recall   specificity   balanced   plain
  incumbent draw0     81.7%       79.6%       80.6%    80.3%
  incumbent draw1     81.7%       83.9%       82.8%    83.2%
  gpt-5.5             95.8%       74.5%       85.1%    81.7%
```

Its extra keeps land on **10 genuine catches and 9 false alarms** — near 1:1.
That is the signature of a **shifted dismissal threshold, not better
discrimination**. Plain accuracy is unmoved (inside the floor); balanced
accuracy rises ~4 points only because the population is imbalanced (137 correct
vs 71 overfitting).

## Part B — the frozen contradiction question, gpt-5.5

Same question, same 91 cases (24 accusing + 67 guard), no rewording.

| criterion | required | incumbent | gpt-5.5 | |
|---|---|---|---|---|
| 1. contradiction-class hits | ≥7 of ~11 | 2 | **2** | **FAIL** |
| 2. guards answer NONE | ≥95% (≤3 wrong voids) | 10 wrong (85.1%) | **10 wrong (85.1%)** | **FAIL** |
| 3. NONE on non-contradiction | 0 voided | 5 | **5** | **FAIL** |

Criterion 2 kills it outright, as the protocol said in advance.

The numbers are not merely similar, they are **identical in count** — 7 grounded
voids among accusers, 10 wrong voids among guards — and they land on the *same
wrong cases*: Closure-62 and Math-30, the two the backtrack classified as **not**
contradiction-class. Both models find plausible-looking quotes rather than real
contradictions.

One genuine difference: errors fell 25 → 7. That is the harness's 300s timeout,
not a model property, and it is not evidence either way.

## Decision, per the pre-registered table

> *same failure shape → the ceiling is architectural; record and close the model
> question.*

**Same shape. The model question is closed.** A newer judge does not engage
differently with the evidence it was already shown: it fails the contradiction
question in the same way, on the same cases, at the same rate.

What it does instead is sit at a different dismissal threshold — and a threshold
is not something a model swap is needed to obtain. If the recall/precision
balance should move, move it deliberately and measure it against both guards,
rather than buying it as a side effect of a model change.

**Not opened:** (a) re-test on a future stronger model, (b) cross-model
agreement. Both were conditional on a *different* failure shape, and the shape
did not change.

## Cost, including waste

```
  part A  gpt-5.5   2,537,736 tokens   241 calls
  floor   gpt-5.4   5,032,391 tokens   477 calls
  part B  gpt-5.5   ~1M (91 cases)
```

Plus two self-inflicted losses, both harness faults rather than experiment
faults, both now fixed:

1. **Floor collision** — a timed-out compound tool call kept running and fired a
   second launch into the same output directory; `verifier_replay` opens
   `results.jsonl` with `'w'`, so it truncated the first run's 33 minutes to
   zero (188,628 bytes, 11,615 non-null, 20 of ~440 rows parseable — a sparse
   file the surviving process kept writing into at its old offset). ~2M tokens.
2. **Part B deadlock** — main thread parked on an `ex.map` future, no sockets,
   no CPU, for 83 minutes; results were only written at the end, so ~90
   completed calls were lost. ~1M tokens.

Both share one cause: **work held in memory until the end is work that can be
destroyed.** The runner now writes and flushes per case and resumes by skip.
`verifier_replay` still truncates an occupied output directory rather than
refusing it — recorded as a small standing guard to add, deliberately NOT slipped
into the closed batch.
