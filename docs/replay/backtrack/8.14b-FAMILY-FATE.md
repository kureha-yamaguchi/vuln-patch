# 8.14b — Winning-family fate: INCONCLUSIVE. The method cannot produce the count.

**Result: the gate question is NOT answered.** This document supersedes the
earlier version, whose "≥5 of 11, a floor" claim was wrong.

## What happened

The method: *winning family* = the check names the judge KEPT on a roll where the
bug was caught; then test whether a family of that shape was proposed in the
missed roll. The test is name matching, because that is all the traces support.

Matching threshold changes the answer completely:

| criterion | never-proposed count |
|---|---|
| ≥2 shared name tokens (first attempt) | 5 of 11 |
| shared leading class token (second attempt) | **1 of 11** |

Same data, same rolls, same definition of "winner". Only the string-matching rule
changed, and the finding inverted.

## Both thresholds are demonstrably wrong

**The strict one produced a false ABSENT, verified concretely.** It marked
final30A Chart-19 "never proposed". But Chart-19's winning family — kept in
night20c — is `categoryplot_getRangeAxisIndex_null_rejected_independent_of_`, and
final30A proposed **6 categoryplot-\* families**. Item 2d had independently
recorded 12 of them in that very roll. The winner shares only the token
`categoryplot` with proposals like `categoryplot-range-axis-index-roundtrip`, so a
≥2-token rule cannot see it.

This also refutes the earlier doc's central methodological claim — that loose
matching "errs toward false present, never false absent". That covers *looseness*;
it does not cover **name drift between rolls**. LLM-assigned names for the same
conceptual family differ per roll, so a strict rule reads drift as absence.

**The loose one over-matches badly.** Matching on the leading class token alone
gives 1 winner family "matching" 10–19 proposals on six separate rows. A head
token like `categoryplot` or a bare class name matches nearly everything the leg
proposed about that class, so almost nothing can fail the test.

## The honest conclusion

**String matching over LLM-assigned rule names cannot resolve whether a
conceptual family was proposed.** The names are generated fresh per roll and do
not share a stable vocabulary. Between a rule that is too strict to survive drift
and one too loose to exclude anything, there is no principled threshold available
from the trace text.

**So the 8.14b gate stands unresolved.** The invention items (8.17, 8.9, 8.5's
third arm) are neither licensed nor killed by this read.

## What IS reliable from this exercise

1. **final30A Chart-19's winning family WAS proposed.** Two independent routes
   agree (this read plus 2d's 12 categoryplot rules). Chart-19's misses are not
   invention failures — consistent with 2d's original finding that its family died
   at *construction*.
2. **final30A Lang-63 is the strongest never-proposed candidate**: 4 identified
   winner families, 0 matches even under the loose criterion.
3. **Math-104 is family-unobservable, not lever-less** — corrected per review. It
   was never caught in any of the three runs, so no winning family can be
   extracted; but 2 of its 3 instances are fired-and-dismissed and therefore sit
   inside 8.18's read population, and its step-1 adjudication is on record as
   drift-kill B with the dev fix at 6.77e-15 satisfying the check and the overfit
   at 8.2e-10 violating it. 8.18 decides its class.

## What would resolve the gate

Not a better string rule. Semantic adjudication: for each missed leg, read the
winning check's *asserted property* and ask whether any proposed rule in the
missed roll asserts the same property under a different name. That is a manual
read of ~11 legs — free, but a real reading job, not a script.

Recorded as the honest state: **the invention-class size is unmeasured**, and the
levers gated on it remain gated.
