# The test the audit specified cannot decide it, and here is why.

## The specified test, and its answer

> Read the Lang-27-o winning-harness citation; if the @throws text appears,
> promote to validated and stop asking.

**The block was never delivered on ANY Lang-27 leg.**

```
  Lang-27 legs in the archive : 44
  ...with a trace             : 22
  ...where A5 was DELIVERED   :  0 of 22
```

Zero occurrences of `DOCUMENTED PRECONDITIONS`, `@throws` or `@param` in any of
them. So the hypothesis — that A5 was co-responsible for the Lang-27 first catch
because the type-suffix contract lives in javadoc — **is refuted at the root**.
It is not that the contract failed to help; the block carrying it was absent.

**No promotion.** That route is closed, definitively rather than
inconclusively.

## But A5 is NOT inert, so deletion is not the corollary

```
  archived traces total        : 648
  ...with the A5 block delivered: 191  = 29%
  in the four 30-leg runs      :  40 of 120 legs
```

Unlike the family-novelty gate (458 evaluations, 0 actions), this block reaches a
third of legs. Whether it CHANGES anything there is a separate question — and it
is the question the audit's Lang-27 test was a proxy for.

## Why I am not answering that question by grep

The obvious measurement says the block is used in **40 of 40** delivered legs.
That number is an artefact, and the control proves it:

```
  donor leg's constraint tokens : ['Random', 'generator', 'number']
  legs where the block was NOT delivered       : 80
  ...yet a donor token appears in them anyway  : 46 = 57%
```

The tokens a javadoc `@param`/`@throws` line contains are ordinary domain
vocabulary — parameter names, type names, the word "generator". They appear in
harnesses about the same class whether or not anyone was shown the javadoc. A
matcher that hits 57% of legs which never saw the block is measuring vocabulary
overlap, not use, and its 40/40 on delivered legs means nothing.

This is the same failure the A4 grep was flagged for and the same one that
inflated four counts earlier this cycle: **a perfect score is the fingerprint of
a matcher that cannot fail.**

## Status: QUEUED with a decidable test, not deleted on a bad measurement

A5 stays. Deleting it would rest on a number I have just shown to be
meaningless, and keeping it rests on nothing — so the honest state is unresolved
with the resolution named.

**The decidable test**, for whenever a run is being spent anyway: an A/B on the
block alone. Same legs, block on and off, comparing accepted-harness behaviour
on inputs the javadoc declares INVALID — which is what the block actually asks
for ("build inputs that satisfy these constraints by construction"). That is a
behavioural difference a grep cannot see and an A/B can.

Cost: it rides any run that is already happening; it needs no dedicated spend.
Until then A5's token cost is bounded and known: 29% of legs, ~900 characters
capped.
