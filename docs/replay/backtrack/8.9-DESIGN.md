# 8.9 — Family persistence. DESIGN NOTE ONLY; gate is a live A/B, not this doc.

**Target station.** `relations/relation_synth.py` round structure, and the
harness generation loop in `harness/campaign.py`.

**Failure mode it addresses.** The invention lottery. A check family gets
proposed in one roll and lands in `relations_not_implemented`; next roll it is
not proposed at all. Lang-63's winning family behaved exactly this way. The
pipeline's recall then depends on which families happened to be invented on the
day, which is variance we can see but not currently reduce.

## What 8.14c settled, and what it did not

8.14c resolved what the retracted 8.14b could not: **final30B Lang-60 is the one
confirmed never-proposed miss** — nothing that roll asserts `contains()`
non-mutation. night20c Lang-60 is ambiguous and stays ambiguous.

So the addressable class is **1 confirmed + 3 ambiguous out of 14 misses**.
Invention is the *minor* station. Judge dismissal is the major one (10 of 14),
and it is measured 94% correct, which is why cycle 8 closed the recall thread
rather than continuing it.

**The gate is a live A/B, priced against a class of 1–4 legs.** Archival reading
cannot decide this — 8.14c established that the invented-vs-too-weak boundary is
not drawable from traces, because a family that was proposed and screened out
leaves the same trace shadow as one never proposed at all.

## The design constraint that the 8.14b retraction imposes

**Persistence must track families by ASSERTED PROPERTY, never by generated
name.**

This is not a preference. 8.14b's whole result inverted when only the
string-matching threshold changed, 5 → 1, and the retraction's finding was that
generated names have **no stable vocabulary across rolls**: the same property is
called `contains-nonmutation` in one roll and `relation-contains-stable` in the
next. A persistence mechanism keyed on names would persist nothing reliably and
would report success by counting name collisions.

What "asserted property" means concretely, and it has to be pinned before
building: the (method-or-observable, relation-kind, argument-role) triple the
check asserts — e.g. *(`contains`, does-not-mutate, receiver)*. Two families are
the same family when that triple matches, whatever they are called. Anything
looser is name matching with extra steps.

## What must be priced before building

**1. Slot competition.** Persisted families occupy `--synth_max_rules` slots.
Every slot a persisted family takes is a slot a newly invented family does not
get. The mechanism therefore trades invention variance for invention *volume*,
and if the mined/invented pool is already the binding constraint, persistence
can reduce recall while looking like it protects it. This must be measured, not
argued.

**2. Interaction with the novelty gate.** The novelty gate deliberately steers
synthesis AWAY from families already covered. Persistence deliberately re-
proposes families already seen. **These two mechanisms pull in opposite
directions and have never been run together.** Either the novelty gate must
exempt persisted families explicitly, or the two will fight and the outcome will
be whichever one happens to run last — a coin flip dressed as a design.

**3. Interaction with 8.17.** Both 8.9 and 8.17 are anti-lottery mechanisms and
neither has been measured with the other. If both ship, neither's contribution
is attributable. They must be measured separately or not at all.

## The hard boundary

**Run-local only. Nothing crosses runs.** Persisting a family from one run into
another is benchmark farming under the standing rule, and the rule is not
negotiable here: within-run sharing between a bug's legs is the permitted
boundary and this mechanism lives inside it. A persistence store that outlives a
run is a different mechanism and is forbidden.

## Guard plan

Persistence pushes toward **more checks**, therefore toward **more firings**,
therefore toward accusation. Its guard is the **38-row correct-dismissal
fixture** — if re-proposing families manufactures firings on correct patches, it
costs precision at exactly the point the pipeline has no headroom.

Secondary: the 67-row genuine-catch fixture, for the slot-competition damage
(a persisted family crowding out the family that would have caught something).

## Done when

This note exists. **Build only behind a live A/B whose cost is justified against
a 1–4 leg class** — which, stated plainly, is a weak justification, and this note
should not pretend otherwise.
