# `findings/` — Project Zero pipeline outputs

Two kinds of artifacts live here. **Pipeline outputs** (`pipeline/`)
are machine-generated by the `discover/` package one directory up and
can be regenerated at any time. **Human-curated research** lives in
`verified/`. The Liu et al. Linux-kernel reference dataset that used
to sit alongside has moved to its own home at `../../linux_kernel/`.

## Layout

```
findings/
├── README.md                  ← this file
├── seeds_table.md             ← primary human-readable report
│                                (auto-regenerated, at the top level
│                                so a reader hits it first)
│
├── pipeline/                  ← Pipeline JSON/CSV
│   ├── candidates.json          (regeneratable; .json gitignored)
│   ├── seeds.json
│   ├── seeds.csv
│   ├── deep_relate.json
│   ├── deep_relate.csv
│   └── codebase_audit.json
│
└── verified/                  ← Human / scripted verification
    ├── README.md
    ├── findings_table_claude.md   per-row verification of every
    │                              confirmed seed pair
    ├── findings_urls.md           three-tier patch-URL table
    │                              (resolved / lookup-needed /
    │                              closed-source) + iterated results
    └── resolve_remaining_cls.py   Gerrit / NVD / GHSL resolver
                                   that produced the iterated entries
                                   in findings_urls.md
```

## Pipeline phases → which artifact

```
   run_p0_harvest             run_diff_relate         run_inspect_unsure        make_seeds_table
         │                          │                          │                         │
         ▼                          ▼                          ▼                         ▼
  pipeline/candidates.json   pipeline/deep_relate.{json,csv}   pipeline/         seeds_table.md
  pipeline/seeds.{json,csv}                                    codebase_audit.json    (at root)
```

```jsonc
                                                 // e.g. "chromium-p0:2280"
  "evidence":       [{"url": "...", "quote": "...",
                      "source_kind": "rca|narrative|narrative_table|sheet"}],
  "sheet_year":     2022,
  "vendor":         "Google",
  "product":        "Chrome",
  "confirmed":      true,                       // llm_confirmed OR
                                                 // overlap_status=="overlap"
  // prose-LLM verifier
  "llm_confirmed":         true,
  "llm_relationship_kind": "incomplete_fix",
  "llm_same_codebase":     true,
  "llm_is_incomplete_fix_cause": true,
  "llm_confidence":        0.95,
  "llm_reasoning":         "The RCA explicitly states ...",
  "llm_best_evidence_url": "https://github.com/.../CVE-2022-1096.md",
  "llm_cited_sentence":    "CVE-2022-1096 was incompletely fixed.",
  // URL / file-overlap verifier
  "overlap_status":  "overlap",                 // overlap | no_overlap | partial | no_patches
  "overlap_files":   ["src/objects/objects.cc"],

  "prior_patch_url": "https://chromium.googlesource.com/v8/v8/+/f9857fdf...",
  "upstream_commits":     [...],                // URLs from RCA prose
```


### `seeds_table.md`

Markdown report combining everything above into purpose-driven buckets
for the incomplete-fix-database use case:

- **INCOMPLETE_FIX** — gold target (patches that were incomplete and
  caused a new CVE).
- **SAME_ROOT_CAUSE** — sibling pairs sharing a root cause / bug class
  but not strict incomplete-fix.
- **UNRELATED** — deep verifier read both diffs and rejected.
- **DROPPED** — codebase audit says cross-vendor, or self-pair.
- **UNSURE** — low-confidence prose without a clear fit.

Each row carries the inferred software / vendor, full skip reasons,
codebase-audit explanation, and clickable evidence + patch URLs.

## What to look at first

- **For the dataset**: [seeds_table.md](seeds_table.md) (grouped
  Markdown report at root) and [pipeline/seeds.csv](pipeline/seeds.csv)
  (flat CSV).
- **For per-pair human verification**: [verified/findings_table_claude.md](verified/findings_table_claude.md).
- **For patch URLs (3 tiers)**: [verified/findings_urls.md](verified/findings_urls.md).
- **For LLM `same_codebase` disagreements** worth manual review:
  [pipeline/codebase_audit.json](pipeline/codebase_audit.json) filtered
  to `verdict == "disagrees"`.
- **For deep code-level confirmations**: [pipeline/deep_relate.csv](pipeline/deep_relate.csv)
  (only related rows).
